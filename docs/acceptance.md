# 验收规则

## 完整版本验收

用同一个完整版本验收各项玩法和任务，并覆盖下列真机与存档场景。主流程从建角到结局沿用同一份角色存档。两条门派路线和互斥的剧情选择分别建立角色核对。全部计划内容完成并通过验收后，再考虑部署上线。[玩法模块索引](gameplay-rules.md) · [任务流程核对](modules/quests/design.md#任务流程核对)

### 真机验证

| 场景 | 检查步骤与通过条件 |
| --- | --- |
| 工程入口 | 在登记的工具链上构建调试包并安装。打开后进入横屏，能看到地图、虚拟摇杆和中文反馈 |
| 触控与布局 | 在 16:9 与 20:9 横屏比例下分别检查。左下摇杆点拨一步、拨住连续移动，回中或松手停步。关键文字与按钮避开系统手势区及刘海 |
| 背包与装备 | 在 16:9 与 20:9 横屏核对物品格、筛选和五个装备位。交付师门接引前后分别查看装备，确认限制提示和解锁。使用一份口粮或金疮膏，核对数量和读数。通过「查看装备位」定位、替换和卸下，重启核对槽位、持有及可用数量。用含有装备物品的 v8 档核对旧物品保留且装备位为空 |
| 小河连通 | 从镇西河口沿水路检查到镇东出口，桥下不断水、树和柴棚不封河；镇内无孤立河段或断头水格。北街新桥可南北通行，走向河水受阻且不改变存档。两比例核对全图与桥位，旧 v5／内容 2 原位续玩 |
| 小镇街巷引导 | 16:9 和 20:9 横屏检查镇东入口到武馆的石路、药摊与衙门支路，以及镇西家门桥头和南井木牌。出家门五步到取水格。核对院墙与阻挡格、已开放箭头与未开放木栅标记 |
| 建筑辨识 | 在 16:9 与 20:9 横屏走过镇西和镇东，靠各自的门面、门边器物和实体招牌区分七栋建筑。路面没有建筑名称标签，店招和匾额上的字清楚可读，穿门后到达对应室内 |
| 主角四向行走 | 男女角色在两种横屏比例验证正面、背面和左右侧面，连续走路交替迈腿、反向摆臂，停步收脚；碰撞不空走、穿门不残留步态，重启保持位置、朝向与时间。帧间身高和落脚点不跳变 |
| 装备外观 | 男女角色在地图和装备页核对轻木棍、布帽、行脚衣、布护腕和软底布鞋。原地穿戴和卸下时核对对应部位刷新，换剑时检查轻木棍收起，重启继续后确认外观与槽位一致。四向走路和停步时检查棍身和护具跟随姿势，分别在 16:9 和 20:9 核对全套穿戴的效果 |
| 师门接引 | 在两种横屏比例中分别用两派角色打开师父的「师门安排」。只学基本拳脚时显示缺少的本门拳法。学齐后依次接取、确认安排、交付。确认后重启仍可阅读试武对手和备战地点指引。交付一次领取轻木棍、20 铜钱和两项棍法，记录首次棍类运用。模拟交付写入失败时保留待交付存档，重试并重启后只有一次奖励，且不能重复办理 |
| 开局护具购买 | 交付师门接引前后从镇西裁缝店柜台打开「查看护具」。核对两种横屏比例下的余额、四件售价和未解锁提示。使用接引奖励的 20 铜钱买齐四件，余额为零，再尝试购买并检查缺额与持有量。穿戴四件护具并持棍，重启后核对余额、背包、槽位和地图外观 |
| 镇西生活细节 | 两种比例核对四扇门、井边、桥头未被器物遮住。继续游戏的异步读取完成、地图视图可见后再抓场景截图，静止画面对比从首帧稳定后开始。地图静置时水纹、晾衣、炊烟和鸡猫动态可见，角色位置、游戏时间和存档字节保持不变；返回主菜单或后台停止环境动画，回来及重启仍保持进度。系统关闭动画后场景静止但器物仍显示 |
| 文字战斗 | 在两种横屏比例下核对左右栏、固定操作入口，以及普攻、特殊招式和状态变化的文字与数值同步。按样例检查分段播放、一键显示整回合、回看、读档和战斗结果页。[战斗页面验收](modules/combat.md#战斗页面验收) |
| 进度恢复 | 在保存成功后切到后台，再回到应用。结束进程后重新启动，选择继续，恢复到最后一次成功保存的位置 |

比例覆盖可由真机与模拟器共同完成，至少用一台 Android 手机验证触控、进后台和回到前台的实际行为。

### 开局验收

| 场景 | 检查步骤与通过条件 |
| --- | --- |
| 离线开局流程 | 开启飞行模式，选定角色性别并分配四维。建角后查看人物面板的相貌描述。打开老婆婆的对话，核对随机派发一件家务。做完后原地核对铜钱、潜能和实战经验。向老婆婆购买口粮，再到井边饮水。向师父接取校场口信，达成目标后交付领潜能。拜师和习武后打完切磋，获胜并确认结果后继续探索 |
| 开局回合内核 | 从陪练交互格取建角快照，用同一组抽值比较未习武、基本拳脚与两派运用的普攻。核对双方顺序、决定胜负后立即停手、探索时间和饥渴，以及回合状态序列化后相同动作的结果。[开局战斗验收](modules/combat.md#开局) · [T08 实测](task-overview.md#t08-验收) |
| NPC 对话与开局委托 | 在 16:9 与 20:9 横屏检查事务和话题均可点选。从任务页核对当前目标与交付人。任务达到待交付后强停再继续，核对选定目标和轮次。故意让交付写入失败，检查旧档保留，恢复写入后重试一次，核对奖励和已交付标记一同保存。[对白验收](modules/npcs/dialogue.md#验收场景) · [委托验收](modules/quests/README.md#开局) |

角色建成后按小镇格图核对可达性、交互站位和三条家务路线，再检查各玩法模块的开局场景。[小镇地图验收](modules/world/town.md#接入与验收) · [玩法模块验收](#玩法模块验收)

### 成长阶段验收

- 用同一角色核对接引同时授予基本棍法、校场棍法、轻木棍与 20 铜钱。穿上缝补摊共花 16 铜钱的三件护具再进试武。试武交付后复核货单，分别确认两派和四派信物后再查新增商品。[备战货单与验收](modules/items.md#成长阶段) · [接引授艺](modules/quests/design.md#师门接引)
- 用青衡门、渡川门两个档各走完入门、试武、请教、自练和武学切换。分别验证一项本门兵器招和防御招式，同时核对实际装备门槛和重启后的运用项、内力与状态次数。[门派武学验收](modules/martial-arts.md#验收场景)

### 探索、支线与终局验收

- 从新建角色开始，以飞行模式走到原创主线结局。支线及隐藏内容按各自的入口和结果逐项验收。
- 验证河埠钓鱼、换镜和换衣，按取得与参悟条件学到两册秘笈的招式。从两条门派成长路线分别集齐六派信物。第六枚待确认时重启，再确认并去合印门验印，核对六枚持有记录及验印状态。[交换、藏书与信物验收](modules/world.md#探索与剧情)
- 用两条门派路线完成验印与共同的主线选择，进入同一场终局挑战。胜利后按主线选择和已发生事件核对结局，重启恢复保存的结局与通关标记。[终局挑战](modules/world.md#终局挑战)

### 存档验证

- 在 T03 调试包中，新建样例后退到后台再返回，强停并重启后点「继续游戏」。两处均核对已存的样例内容版本和位置。盘上无档时继续入口不可用。有档时取消新游戏确认，核对原档字节与位置。
- 当前包建角后出生在 `player_home (6,2)`、时间 0。向东撞床，位置与时间不变。向南三步、向东两步出门。用 16:9 和 20:9 游戏画面核对错开的卧房门、灶房侧门、墙角、家具占地和界面遮挡。街外西一步回屋到 `(7,5)`，核对一次穿门计一步。四栋建筑往返、桥梁与撞水按[小镇验收](modules/world/town.md#接入与验收)检查，屋内强停后继续应保持存档原字节。
- 用 [中断样例](../app/src/test/resources/saves/interrupted.json) 模拟仅写入 `save.json.new` 就中断。有正式档时重启应继续最后一次提交，无正式档时应显示「暂无存档」。让下一次提交失败，核对原档保留及「重试保存」。恢复写入后点重试，核对同一份角色状态或同一步移动成功提交。将坏档放入正式槽位时检查错误提示及原字节，同意覆盖并完成建角后才替换。
- 用 [v1 样例](../app/src/test/resources/saves/v1-location.json) 和 T03 的 v2 样例验证三个旧地点 ID 的坐标对应。v1 同时补齐缺失的内容版本。继续游戏先读出内存迁移结果，成功行动后写入当前结构。用未知结构版、内容版本和地点分别验证无法继续的提示。[旧样例位置对应](modules/world/town.md#接入与验收)
- 从床边按新格图 19 步到老婆婆屋内，从对话菜单查看售价 4 和余额 12。购买后余额 8、口粮 1。重启食用后口粮与饥饿归零，时间仍为 19。饱足食用及铜钱 3 时购买应保留原档。到南井 `(5,8)` 且口渴时可饮水，离井入口收起。购买保存失败保留原档，重试只扣一次款。v3／v4、内容版本 1 迁移后保留属性、资源与背包，旧地图非法坐标拒绝迁移。v5 的缺失委托与好感从默认值开始。内容版本 2 在镇上和家中可走格原位恢复，家中新占用的格迁至主卧床边，保留时间和资源。[地图迁移证据](task-overview.md#镇西布局修正验收)
- 继续已交付校场口信的 v6 存档，核对 26 潜能、交付进度和位置，首次拜师或请教保存为当前结构。阻止本门拳法入门的暂存写入，核对旧余额、武学等级和运用保持。重试后只扣一次费，重启能恢复本门拳法及运用。
- 继续 v7 探索存档，核对原状态，成功行动后写 v8。用开局切磋样例在回合、胜利待领、死亡三处强停并继续。对比连续游玩与读档后的下一回合、日志和掉落。阻止末回合、确认战利品与读取战前的写入，核对最近一次正式存档的进度。排除写入障碍后用相同操作或「重试保存」恢复。核对胜利待领、被放过后的探索和死亡读档完成时均已清除战前快照。[战利品验收](modules/items.md#开局) · [战败验收](modules/combat.md#战败处置)
- 从开局沿同一份存档推进到中期和终局。在各阶段结束进程并继续游戏，核对任务、门派归属、内力和伤势等状态随角色进度保存。重开人物面板核对相貌描述，从内部状态验证读档沿用建角时保存的幸运和相貌档位。[角色验收场景](modules/character.md#验收场景)
- 正式挑战获胜选择处置前结束进程，核对回到最近一次保存的战斗。确认处置后重启，核对完整结果和 NPC 状态一起保存。[战斗页面验收](modules/combat.md#战斗页面验收)
- 涉及存档或内容结构变更时，用受支持的旧存档结构样例测试兼容读档，核对角色、位置、已完成任务和奖励结算。旧结构缺少有效气血上限时，用已存气血上限补齐，并保留已存当前气血。

## 按改动选择验证

| 改动范围 | 完成证据 |
| --- | --- |
| 项目文档 | 核对实际文件、相对链接、当前阶段、模块名和已登记命令 |
| `game-core` 与内容配置 | 在 JVM 测试中检查相关规则、配置引用、失败分支和随机结果可复现性 |
| `app` 界面与输入 | 调试包可构建并安装，按影响范围完成横屏布局、触控与日志滚动检查 |
| 存档与生命周期 | 验证重开、进程重启、写入中断和受影响版本的旧档恢复 |

Gradle 构建、单元测试和安装命令见 [README.md](../README.md#本地构建与安装)。T01 核对原生横屏启动页、触控反馈、前后台切换与冷启动。T02 核对包内样例的启动与位置反馈，并用无效引用复验 `:app:assembleDebug` 在内容校验失败时退出。T03 核对单槽提交、重开与旧档恢复。T04 检查小镇贴图、摇杆移动、时间结算和角色存档。验收时分别记录实际执行的检查、结果和待验证项。[T03 复验记录](task-overview.md#t03-复验记录)

首个 Gradle 工程能在本地重复运行 `game-core` 的 JVM 测试和 `app` 的 Debug 构建，且配置了 Git 远端后，CI 复用这两项检查。工程建立后，存档迁移、奖励结算或模块边界调整可按需使用只读审查。
