# 任务总览生成提示词

```text
你负责根据白金项目现有需求编排开发任务。将结果写入 docs/task-overview.md，使接手的人能找到下一项可开工的任务、所需前置、交付物和完成证据。

先读取 README.md、AGENTS.md、GLOSSARY.md、docs/gameplay.md、docs/gameplay-rules.md、docs/architecture.md、docs/acceptance.md，以及模块文档和相关 ADR。核对工作区已经存在的工程、内容配置和检查入口。引用的掌机版资料按项目文档的用途处理，项目玩法和命名以现行规约为准。

沿用 Android 原生 Kotlin 横屏、Gradle Wrapper 和 app → game-core 的模块依赖。按单主线安排工作，给出能实际接续的顺序。地图、角色、武学、战斗、任务、物品、剧情和验收均纳入同一个完整版本。开发里程碑用于验证工程和玩法流程。

先找出已经确定的玩法与尚缺的内容。把地图通路、人物或对手、任务候选、主线和结局等缺项写成有交付物的设计任务，并注明它们具体阻塞哪项实现或验收。遇到文档冲突时给出出处、待确认的问题和可继续的独立工作。所需样例可用于规则测试和界面联调，完整版本以实际内容验收。

每项任务使用稳定编号。任务粒度以一次能交付和复验的能力为准，列出名称、类型、直接前置、涉及的模块或文档、可见交付物、通过条件和当前状态。前置引用任务编号，并说明实际依赖的数据或能力。找出循环、重复范围和跨模块归属错误后再定顺序。

给出几个可运行的开发里程碑，至少说明工程构建、开局连通、成长与探索连通、完整通关的验收证据。按现有验收规则安排 JVM、调试包、横屏触控、应用重启和存档边界检查。分别核对已保存回合、待领战利品、选择处置前后的恢复，以及两条门派路线的通关。命令和版本以已建立的工程为依据。

交付前核对任务编号唯一、前置真实且无环、已确认范围都有任务、每项任务有可检查的产物或行为。用相对链接指向实际需求和验收章节。依据工作区事实标记状态，README 记录当前工程阶段，任务总览记录执行顺序和任务状态。输出 Markdown 和简短的校验结果。
```
