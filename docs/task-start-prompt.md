# 白金项目开工提示词

在白金项目目录打开 Codex，复制下面整段。指定任务时，在末尾加上「本次只做 T01」等任务编号。[任务总览与当前顺序](task-overview.md#当前开工顺序) · [验收规则](acceptance.md#按改动选择验证)

```text
根据 docs/task-overview.md 领取并完成一项白金项目任务。本轮交付该任务的产物和可复验的证据。

1. 先读根目录 README.md、AGENTS.md、docs/task-overview.md 和 docs/acceptance.md。核对当前工程阶段、工作区已有改动、内容配置和可执行检查。选定任务后，读该行引用的需求、模块文档及相关 ADR。保留已有改动，复用可用的实现和数据。

2. 用户指定了编号时，按该项推进并逐个验证直接前置的实际产物。未指定时，先接续可推进的「进行中」或「待验收」任务，再按总览顺序选择第一项前置齐备的任务。一次推进一项。遇到缺少的前置，记录任务编号、所缺产物及影响。先完成授权范围内的独立工作，按总览接续时可顺序选择下一项前置齐备的任务。

3. 开工时简要说明任务编号、直接前置、交付物和通过条件，将该项标为「进行中」，随后直接实施。设计任务把可供下游使用的定稿产物写回模块文档，遇到文档冲突时留下出处、待确认问题及被阻塞的实现。人物称呼与掌机版资料按 AGENTS.md 处理。工程任务沿用 Android 原生 Kotlin 横屏、Gradle Wrapper 和 app → game-core。纯 Kotlin 内核处理规则与状态，app 负责 Android 界面、输入、资源和存档。配置沿用稳定 ID，奖励或扣除与对应进度一起提交。

4. 按本任务的通过条件复验。规则和配置用 JVM 检查正常、边界和失败场景。Android 改动按范围核对 Debug 包、安装、横屏触控和生命周期。存档改动检查相关重启、写入中断与旧档恢复。涉及战斗时按场次分别核对已保存回合、待领战利品、选择处置前后。样例用于规则测试与联调，完整通关用同一构建的正式内容，分别验证青衡门和渡川门。命令与版本取自实际工程。首次建立工程时，固定实际工具链并跑通 Wrapper 的 JVM 测试和 Debug 构建，把版本、命令和安装入口登记到 README.md。

5. 交付后用同一编号更新任务行，附产物位置和实测证据。仍缺前置则标「待前置」，产物已交付、检查待执行则标「待验收」，通过条件均有证据才标「已完成」。工程阶段或构建安装入口变化时同步 README.md。最终给出本轮编号和状态、交付物、实际运行的检查及结果、仍待验证或阻塞的事项，以及下一项可开工编号。
```
