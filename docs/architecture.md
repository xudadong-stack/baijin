# 模块边界与架构

## 模块与依赖

| 模块 | 职责 |
| --- | --- |
| `app` | Android 启动和生命周期、横屏布局、触屏命令、状态呈现、资源读取、文件读写及存档迁移 |
| `game-core` | Kotlin/JVM 游戏规则与状态，负责移动、角色属性、NPC 关系、委托与差事、潜能、实战经验、武学、战斗、奖励、游戏时间、补给与自然恢复，以及内容规则和引用校验 |

依赖方向为 **`app` → `game-core`**。`game-core` 的入口通过普通 Kotlin 数据表达状态、内容、动作和处理结果，可以在桌面 JVM 上直接运行和测试。Android 控件、文件路径和生命周期留在 `app`。

选型与模块拆分理由见 [ADR 0001](adr/0001-native-android-and-kotlin-game-core.md)。

## 动作与状态

1. `app` 将触控转换成移动、交互、购买口粮、食用口粮、饮水、习武、普通攻击、确认战利品、选择获胜处置或读取战前存档等玩家动作。地图和菜单展示同一份当前游戏状态。
2. `game-core` 根据当前状态和内容配置校验动作，产生下一状态及显示所需的结果。无法执行时返回具体原因，界面据此呈现反馈。
3. `app` 按顺序提交会改变进度的结果。存档提交成功后显示对应的已完成状态。委托交付标记随当场奖励或待领记录一并提交。潜能扣除与武学等级变化成对提交。切磋获胜时保存胜负和本场确定的掉落结果，包含空掉落。确认结果时再提交背包变化、本场已确认标记和探索状态。[ADR 0003](adr/0003-save-sparring-result-before-claim.md)

当前 `GameEngine.dispatch(state, action)` 接收角色快照和动作。`Start` 校验性别与配点输入，取一次幸运抽值，再生成初始角色与主角家起点的 `Changed`。移动、穿门和打坐也由同一入口产出完整快照。`app` 提交成功后刷新地图和读数。读档时 `InspectLocation` 校验内容版本、场景坐标及角色数值，返回当前位置、相貌描述和渲染所需的地图配置。规则拒绝的动作返回带具体原因的 `Blocked`。

`GameEngine.dispatch(state, action, sparring)` 用 `BeginSparring` 校验陪练交互格并生成本场编号。已有战斗时，以本场编号和待结算回合编号校验 `AttackSparring`，再由 `SparringState.attack` 结算双方读数、日志、胜负和下一回合种子。继续游戏按已提交进度进入切磋、胜利确认、死亡结果或探索。切磋重新开场使用新的场次编号。[回合续玩](adr/0002-resume-sparring-after-saved-round.md)

切磋回合写入成功后，`app` 从本次行动前的读数开始，播放内核返回的已结算回合。战败被放过时，播完交手再打开已保存的探索进度。播放进度留在界面，重启时直接打开最新保存的完整进度。[战斗页面](modules/combat.md#战斗页面)

符合任务掉落条件的胜利由 `game-core` 将必需物品与普通掉落合并为同一待确认结果。保存与确认入包使用本场战斗的结算记录。[任务必需掉落](modules/items.md#任务必需掉落)

师父和捕快的主动挑战需要由玩家确认获胜处置。`game-core` 返回供结果页展示的最后一回合、可选处置及各选项对服务和路线的影响，`app` 在本次运行中保留这份结算。玩家确认后，最后一回合、胜负、处置及受影响的游戏状态组成一次存档提交。进程重启以最近成功提交的回合为准。[正式挑战的获胜处置](modules/combat.md#正式挑战的获胜处置)

战斗中的命中与闪避共用规则内核的一次随机判定。命中后由规则内核依次结算招架、伤害浮动和防护抵扣。普通伤害大于 0 时，规则内核根据攻方膂力、运用武学、招式和固定幸运计算并判定暴击，确定实际伤害后结算伤势、气血和胜负。武学的威力、招架率与暴击率加成均按当前等级查配置表。相同的起始状态、行动序列和随机种子在同一规则版本下应产生相同的结果。试玩在回合间续玩，存档包含双方战斗状态、本场已保存的文字日志和恢复随机数进度所需的数据。[ADR 0002](adr/0002-resume-sparring-after-saved-round.md)

`game-core` 在角色战败时用对手的善恶值及对该角色的当前好感度确定处置结果。被放过时一并保存结果和包含位置、气血、伤势与消耗的探索状态。被杀时保存死亡结果和战前存档。恢复战前进度是一笔完整状态提交，成功后回到战前的探索界面。[战败处置](modules/combat.md#战败处置)

`game-core` 在探索的成功移动中按顺序结算位置、游戏时间、饥饿度、口渴度和自然恢复，`app` 提交为一份快照。购买时校验售卖 NPC、交互位置和铜钱余额，扣款与口粮入背包一同提交。食用时口粮扣除和饥饿度下降一同提交。饮水时校验角色已到井边，再提交口渴度下降的结果。

探索中的打坐由 `game-core` 逐个结算四个游戏时间单位，`app` 一次提交时间、饥渴与恢复结果。[打坐](modules/character.md#角色成长与吃喝)

`app` 在打开 NPC 对话时发送对话动作。`game-core` 核验交互站位、实战经验与轮次，符合条件时抽取一项家务。派发写入成功后显示本轮对白。做家务时核对轮次、目标和地点，同次提交完成标记与奖励。旧档里已做完未领奖的家务在读档时结算，随下一次成功保存写入。[委托与经济](modules/quests/README.md#委托与经济)

并行任务按任务 ID 保存各自的进度。可重复任务区分当前轮次。寻物交付时按同一状态中的可用数量重验，将扣物、对应轮次的交付状态和奖励结果一起提交。可用数量变化时，重验受影响的进行中或待交付任务并提交新状态。[任务并行与交付](modules/quests/README.md#任务并行与交付)

搬运差事接取时同时提交石料入包与本轮进度。交付由 `game-core` 核对交付 NPC、当前轮次和石料，扣料、奖励与轮次完成标记一同提交。[搬运石料](modules/quests/design.md#搬运石料)

追缉派发时由 `game-core` 确定本轮档位、目标、出没地点、对手配置、接取时间和奖励，`app` 一并提交。重开时读取同一轮记录，时限按已保存的游戏时间判定。进入该轮战斗时按该时点核对本场资格，战斗动作推进独立回合计数。指定交战获胜时，经验、潜能、本轮完成状态和本场结果一起提交。[追缉通缉犯](modules/quests/design.md#追缉通缉犯)

## 横屏界面

主角地图显示由 `TravellerArtwork` 读取男女四向帧图，`WalkCycle` 在每次成功移动中交替左右脚，动画与存档状态分离；穿门、隐藏或关闭系统动画时收脚。

- 探索地图铺满横屏，左下叠加圆形虚拟摇杆，右上提供背包、任务、武学、人物和主菜单。到南井指定位置且口渴时，右侧展开地点和状态栏。摇杆拨住时按正交方向逐步提交移动，回中、松手或退到后台时停止继续发出动作。前一步保存成功后才提交下一步。售卖 NPC 的菜单显示口粮售价和角色铜钱余额，水井的饮水选项在角色到井边时显示。
- NPC 对话由 `game-core` 按善恶偏向、当前好感度和相貌条件返回可选话题。必经任务入口按对应的任务条件独立返回，`app` 在同一对话页呈现对白与确认入口。[交互与对白](modules/npcs/dialogue.md)
- 任务页读取同一份游戏状态，显示任务进度、下一步目标、待满足条件、交付对象及完成状态。继续游戏时恢复已保存的轮次和进度。[任务设计](modules/quests/design.md#任务提示)
- 师父的请教页从内核读取下一等级的费用和缺项。「武学」页从同一快照读取已学等级、运用项和徒手普攻威力。请教成功后，潜能、等级及首次运用随同一快照提交。[开局武学](modules/martial-arts.md#开局)
- 人物面板展示四维、相貌描述等可见信息。`game-core` 根据已保存的性别和相貌档位查出对应描述，`app` 呈现文字。幸运仅供规则结算和存档使用。[相貌](modules/character.md#相貌)
- 战斗时左侧显示双方状态，右侧显示可滚动的战斗日志，右下固定战斗操作。实际进攻命令携带本次加力投入。`game-core` 随回合返回按实际结算排序的日志段和各段对应的读数。普通回合保存后播放，需选择处置的最后一个回合先播放再等确认提交。分段出字、招名加粗、读数更新和滚动由 `app` 处理。「显示整回合」呈现当前回合的完整文字和最终读数，继续游戏使用最近一次已提交的状态。[战斗页面](modules/combat.md#战斗页面) · [特殊招式文字演出](modules/combat.md#特殊招式文字演出)
- 被放过后在探索日志中显示处置结果。死亡结果页显示对手和战败结果，提供「读取战前存档」。
- 中文文本和菜单沿用原生控件。地图用自定义 `View` 的 `onDraw()` 沿 D01 的通行格铺设地面，按对象格摆放贴图，视野跟随保存成功的角色位置。规则通过玩家动作推进。[小镇贴图](art/town-well.md#随包贴图) · [Android 自定义绘制](https://developer.android.com/develop/ui/views/layout/custom-views/custom-drawing)
- 根据横屏可用窗口布局。关键按钮和文字避开刘海、系统栏与手势区，长日志在自己的区域内滚动。[Android 窗口安全区](https://developer.android.com/develop/ui/views/layout/edge-to-edge)

## 内容与本地存档

- 内容 JSON 随应用发布。地点、NPC、任务、武学和物品通过稳定 ID 关联。内容校验覆盖重复 ID、缺失引用和无效数值，随工程接入构建检查。
- 相貌配置提供四维权重、分档阈值和七档描述。内容校验确认分档阈值严格递增，每档均有男角、女角描述。[相貌](modules/character.md#相貌)
- 背包按物品 ID 保存持有量，装备位保存对物品 ID 的穿戴引用。`game-core` 计算可用数量，并在出售、交付和换装时核对占用。穿戴时检查装备门槛，出招时按当前武器检查招式条件。[ADR 0005](adr/0005-count-items-and-equipment-occupancy.md)
- 商品和换物条目关联 NPC、场景、物品、数量、价格及进度门槛。交战按场次查普通掉落表，同一 NPC 承担多个场次时各有对应引用。校验货单、各掉落组、换物条目与任务必需品的 ID 引用和数量，检查投放途径与开放条件。[物品与装备](modules/items.md)
- 一次性交换完成、隐藏秘笈领取分别与对应物品变动一起保存。采集保存可再次取得的游戏时间，参悟保存武学和已参悟记录。六派试艺保存各派线索，信物按门派 ID 记录领取进度，同步提交到确认战利品的状态更新。进入终局时检查已保存的验印结果与主线选择，终局胜利时同时保存结局和通关标记。[多区域探索与支线](modules/world.md#多区域探索与支线) · [终局挑战](modules/world.md#终局挑战)
- 玩家与各 NPC 的基础招架率由各自的角色内容配置提供。NPC 内容配置提供 1 至 100 的固定幸运。武学逐级配置威力、命中、闪避、招架、内力和暴击等适用修正。招式配置引用武学、等级和武器类型，并记录内力费用、进攻参数或防御状态效果。招式的日志内容配置提供原创描写和对应的呈现方式。[武学与战斗](modules/martial-arts.md#运用与出招) · [暴击](modules/combat.md#暴击)
- 存档按武学 ID 记录已习得等级和目标等级的练功进度，保存门派归属、拳脚和各类兵器的运用项，以及轻功、内功、招架的运用项。师门接引的物品、授艺、运用项和任务完成状态同次提交。战斗回合一起保存伤害、内力、状态剩余次数和随机进度。[武学修炼](modules/martial-arts.md#武学与修炼) · [战斗回合](modules/combat.md#战斗规则)
- NPC 的善恶值与初始好感度由内容提供，校验两个字段的整数范围。`game-core` 按稳定 ID 记录 NPC 对当前角色的好感度，游戏事件改变好感度时保存限制在范围内的结果。[战败处置](modules/combat.md#战败处置)
- 游戏使用一个自动存档槽，同一存档贯通开局到终局。存档记录结构版本、角色进度、建角时确定的性别、幸运和相貌档位，以及位置、委托与差事进度、铜钱、潜能、实战经验、背包、NPC 好感度、游戏时间、饥饿度、口渴度和继续当前战斗或回到对应结果页所需的状态。同时至多保留一场待处理的战斗结果。
- 存档同时保存当前角色进度和至多一场切磋。战斗进行中和死亡结果保留完整战前快照。胜利保存本场待确认掉落时即清除战前快照，确认时将入包和已确认场次随探索状态一并保存。战败被放过或完成死亡读档也清除战前快照。[ADR 0004](adr/0004-keep-pre-battle-save.md)
- 建角和游戏动作在规则规定的结算时点保存。`game-core` 在确认建角时生成幸运并用建角四维计算相貌档位，由 `app` 随初始角色状态一次提交。`app` 在进程内串行读写 `filesDir/save.json`，使用 AndroidX `AtomicFile` 先同步 `save.json.new`，再提交完整快照。重启以最近成功提交的状态作为继续入口。[Android 私有存储](https://developer.android.com/training/data-storage/app-specific) · [AtomicFile](https://developer.android.com/reference/androidx/core/util/AtomicFile)
- 写入失败时提示并允许重试提交同一份待保存快照。读档失败时保留文件并提示原因，玩家明确确认新游戏后才替换已有档。兼容的旧档通过版本迁移恢复，迁移前后以存档样例验证角色进度和内容引用。
- 首胜指定挑战时，将经验增量与首胜标记一起保存。高阶请教读取开局以来的累计实战经验。存档保留当前气血、有效气血上限和内力，分别保存声望与通缉。相关玩法按同一份存档中的成长和剧情条件开放。[玩法模块索引](gameplay-rules.md)

当前写入结构 v9、内容版本 3。内容版本 2 读档时保留有效原位，主角家被新墙或家具占用的旧格迁到主卧床边，切磋存档同步迁移战前快照。`state` 保存位置、朝向、角色属性与资源、时间、饥渴、铜钱、背包、装备位及上场切磋的确认或放过记录。`sparring` 保存进行中的切磋或尚待处理的战果。v8 保留背包和切磋进度，缺失的装备位默认为空。v7 原位恢复门派、武学等级和运用项。v6 保留潜能、实战经验、好感度和委托轮次，武学记录默认为空。v5 缺失的潜能和实战经验默认为零，委托与好感记录默认为空。v3 缺背包时补空，v3／v4 的内容版本 1 按 `LegacyWorldLayout` 验证旧坐标并迁到新图，保留角色属性与资源。v1／v2 按旧地点 ID 生成固定样例角色。迁移在内存完成，下次成功行动写 v9。无法读取的原文件保留，保存失败可重试同一份快照。[迁移详情](modules/world/town.md#接入与验收) · [v1 样例](../app/src/test/resources/saves/v1-location.json)

`game-core` 以物品 ID 保存持有总数，以部位保存正在穿戴的物品 ID。可用数量由两项状态计算。切磋开始时读取当时的武器和护具属性。原生背包与装备页使用同一个状态视图，装备和消耗品动作通过 `GameSession` 保存后刷新。[装备占用](adr/0005-count-items-and-equipment-occupancy.md)

师门接引交付时在同一次状态提交中更新任务轮次、铜钱、背包、已学武学和首次棍类运用。内核从配置的接引任务轮次派生 `SectPreparation`，只有已交付才开放备战。穿戴和开局护具货单使用此门槛，`Exploration.sectPreparation` 提供师门安排及后续试武、分阶段货单和内力动作所需的进度。读档后从已保存的任务轮次恢复此进度。[师门接引](modules/quests/design.md#师门接引)

开局护具货单配置商贩 ID、护具 ID 和单价。购买动作复验柜台位置、接引进度、售价与库存计数上限，扣除铜钱与物品入包一并提交。货单及开放条件在读档后由内容与任务状态计算。[开局护具货单](modules/items.md#交易)

### 随包样例与校验

`app` 从 assets 读取 UTF-8 的 [content/sample.json](../app/src/main/assets/content/sample.json)，交由 `game-core` 的 `ContentLoader` 解码和校验。Android 构建在 `preBuild` 前运行 JVM 任务 `:game-core:validateContent`，读取同一份源文件并显示校验失败的 JSON 路径。

- `contentVersion` 为正整数，随状态传给存档入口。场景、地点、出口、NPC、任务、武学和物品的 ID 以小写字母开头，由小写字母、数字和单个下划线组成，同表唯一。镇西场景为 `town`，镇东为 `town_east`，既有 NPC、任务、物品继续保留原稳定 ID。
- 起点和 NPC 的地点引用地点表。任务发布人与交付对象引用 NPC 表，奖励中的物品与授艺分别引用物品和武学表。奖励铜钱、潜能和经验为非负整数。物品数量和授艺等级为正整数，授艺等级以对应武学的最高等级为上限。
- `openingTraining` 引用基本拳脚和各门派的入门拳法。每项开局武学在 `openingLevels` 中配置 1、2 级的标准潜能及进攻参数。内容校验核对门派 ID、武学引用、等级配置及数值。
- `openingSparring` 配置场次 ID、提供切磋的 NPC、对手属性、双方防御、普攻浮动幅度与普通掉落权重表。`requiredLoot` 可按任务 ID、进度和可选的目标 ID 指定必掉物品。对手幸运沿用 NPC 配置。当前运用的拳法用 `openingAttackLines` 按场内出手次数轮换，缺省使用通用徒手描写。[战斗规则](modules/combat.md#战斗规则) · [掉落权重](modules/items.md#普通掉落权重)
- 地图用等宽行保存通行格 `.` 和阻挡格 `#`。地点和出口引用场景内可通行的坐标。对象格与地点同格或正交相邻。`terrain` 独立保存院地、石路、水道、桥和室内地板，水不可通行、桥可通行；`scenery` 保存贴图类型、脚底锚点、尺寸、标签及阻挡占地。渲染层不从阻挡格推断围墙。河道按相邻水格和桥格连接，边缘河口向视口外延伸；镇西、镇东有专用回归检查，保证河网连通、镇内无断头水格及两场景河口对齐。`TownLifeArtwork` 绘制晾衣、菜畦、晒粮、水纹、炊烟和店招文字，并在渲染中应用鸡猫的轻微姿态变化；环境时钟仅驱动可见室外地图重绘，地图隐藏、离开室外或移出窗口时停止，遵循系统关闭动画设置。地面景物缓存在场景绘制数据中，环境动态不调用规则动作或存档。建筑两侧的门用 `destinationExitId` 互相连接，`onEntry` 门在进入门格的一步内切换到对面返程格。返程格为各自门位内侧相邻的通行格。还在等待接续的小镇道路出口朝向格图外。[小镇格图](modules/world/town.md#小镇格图) · [主角家门](modules/world/player-home.md#家门往返)
- `supplies` 配置开局售粮 NPC、口粮物品 ID、价格与饥饿补充量、饮水地点和解渴量。校验 NPC、物品与地点引用、井的类型及正数值。购买、食用和饮水即时结算，不推进游戏时间。背包仅保存已知物品的正数持有量，扣至零时移除条目。
- `creation` 配置四维初值、配点范围、幸运抽值、初始资源和铜钱。`time` 配置饥渴上限、增长与恢复间隔、打坐时长和恢复量。[角色与补给试算](modules/character.md#角色成长与吃喝)
- `appearance.weights` 的四项对应膂力、敏捷、悟性和根骨。六个 `thresholds` 是第 2 至 7 档的最低分，严格递增。七条 `descriptions` 按第 1 至 7 档排列，每档提供男女描述。[相貌规则](modules/character.md#相貌)
