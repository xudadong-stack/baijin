# 模块边界与架构

## 模块与依赖

| 模块 | 职责 |
| --- | --- |
| `app` | Android 启动和生命周期、横屏布局、触屏命令、状态呈现、资源读取、文件读写及存档迁移 |
| `game-core` | Kotlin/JVM 游戏规则与状态，负责移动、角色属性、NPC 关系、委托与差事、潜能、实战经验、武学、战斗、奖励、游戏时间、补给与自然恢复，以及内容规则和引用校验 |

依赖方向为 **`app` → `game-core`**。`game-core` 的入口通过普通 Kotlin 数据表达状态、内容、动作和处理结果，可以在桌面 JVM 上直接运行和测试。Android 控件、文件路径和生命周期留在 `app`。

选型与模块拆分理由见 [ADR 0001](adr/0001-native-android-and-kotlin-game-core.md)。

## 动作与状态

1. `app` 将触控转换成移动、交互、购买口粮、食用口粮、饮水、习武、普通攻击、确认战利品、选择获胜处置或读取战前存档等玩家动作。地图和菜单展示同一份当前游戏状态。
2. `game-core` 根据当前状态和内容配置校验动作，产生下一状态及显示所需的结果。无法执行时返回具体原因，界面据此呈现反馈。
3. `app` 按顺序提交会改变进度的结果。存档提交成功后显示对应的已完成状态。委托交付标记随当场奖励或待领记录一并提交。潜能扣除与武学等级变化成对提交。切磋获胜时保存胜负和本场确定的掉落结果，包含空掉落。确认结果时再提交背包变化、本场已确认标记和探索状态。[ADR 0003](adr/0003-save-sparring-result-before-claim.md)

当前 `GameEngine.dispatch(state, action)` 接收样例状态和动作。`Start` 返回 `Changed`，其中的 `GameState` 保存内容版本和起点 ID。`InspectLocation` 返回 `Display` 供界面显示当前位置。缺少状态、内容版本不匹配或当前地点已缺失时返回 `Blocked`，同时给出对应缺项。T03 使用这些入口初始化和恢复样例状态。

符合任务掉落条件的胜利由 `game-core` 将必需物品与普通掉落合并为同一待确认结果。保存与确认入包使用本场战斗的结算记录。[任务必需掉落](modules/items.md#任务必需掉落)

师父和捕快的主动挑战需要由玩家确认获胜处置。`game-core` 返回供结果页展示的最后一回合、可选处置及各选项对服务和路线的影响，`app` 在本次运行中保留这份结算。玩家确认后，最后一回合、胜负、处置及受影响的游戏状态组成一次存档提交。进程重启以最近成功提交的回合为准。[正式挑战的获胜处置](modules/combat.md#正式挑战的获胜处置)

战斗中的命中与闪避共用规则内核的一次随机判定。命中后由规则内核依次结算招架、伤害浮动和防护抵扣。普通伤害大于 0 时，规则内核根据攻方膂力、运用武学、招式和固定幸运计算并判定暴击，确定实际伤害后结算伤势、气血和胜负。武学的威力、招架率与暴击率加成均按当前等级查配置表。相同的起始状态、行动序列和随机种子在同一规则版本下应产生相同的结果。试玩在回合间续玩，存档包含双方战斗状态、本场已保存的文字日志和恢复随机数进度所需的数据。[ADR 0002](adr/0002-resume-sparring-after-saved-round.md)

`game-core` 在角色战败时用对手的善恶值及对该角色的当前好感度确定处置结果。被放过时一并保存结果和包含位置、气血、伤势与消耗的探索状态。被杀时保存死亡结果和战前存档。恢复战前进度是一笔完整状态提交，成功后回到战前的探索界面。[战败处置](modules/combat.md#战败处置)

`game-core` 在探索的成功移动中按顺序结算位置、游戏时间、饥饿度、口渴度和自然恢复，`app` 提交为一份快照。购买时校验售卖 NPC、交互位置和铜钱余额，扣款与口粮入背包一同提交。食用时口粮扣除和饥饿度下降一同提交。饮水时校验角色已到井边，再提交口渴度下降的结果。

探索中的打坐由 `game-core` 逐个结算四个游戏时间单位，`app` 一次提交时间、饥渴与恢复结果。[打坐](modules/character.md#角色成长与吃喝)

`game-core` 在接取家务时检查累计实战经验低于 5000，并保存本轮选定的家务和进度。完成动作按已接轮次校验地点和目标。交付动作同时提交本轮完成标记及铜钱、潜能和实战经验的增量。重启后从存档中的经验与任务状态判定可接取或可交付。[委托与经济](modules/quests/README.md#委托与经济)

并行任务按任务 ID 保存各自的进度。可重复任务区分当前轮次。寻物交付时按同一状态中的可用数量重验，将扣物、对应轮次的交付状态和奖励发放或登记结果一起提交。可用数量变化时，重验受影响的进行中或待交付任务并提交新状态。[任务并行与交付](modules/quests/README.md#任务并行与交付)

对累计领赏，`game-core` 在交付时按任务与轮次记录一笔已确定的待领奖励。`app` 一次提交该记录、交付进度和应交物品的扣除。玩家确认领赏时，由 `game-core` 核对领赏 NPC、交互位置和本档待领记录，再由 `app` 一次提交资源入账和这批记录的结清。[累计领赏](modules/quests/README.md#累计领赏)

搬运差事接取时同时提交石料入包与本轮进度。交付由 `game-core` 核对交付 NPC、当前轮次和石料，扣料、奖励与轮次完成标记一同提交。[搬运石料](modules/quests/design.md#搬运石料)

追缉派发时由 `game-core` 确定本轮档位、目标、出没地点、对手配置、接取时间和奖励，`app` 一并提交。重开时读取同一轮记录，时限按已保存的游戏时间判定。进入该轮战斗时按该时点核对本场资格，战斗动作推进独立回合计数。指定交战获胜时随本场结果保存待交付状态，向捕快交付时将经验、潜能和本轮完成状态一起提交。[追缉通缉犯](modules/quests/design.md#追缉通缉犯)

## 横屏界面

- 探索时左侧显示地图和方向键，右侧显示角色状态、对话及交互按钮。角色状态可查看饥饿度和口渴度。售卖 NPC 的菜单显示口粮售价和角色铜钱余额，水井的饮水选项在角色到井边时显示。
- NPC 对话由 `game-core` 按善恶偏向、当前好感度和相貌条件返回可选话题。必经任务入口按对应的任务条件独立返回，`app` 在同一对话页呈现对白与确认入口。[交互与对白](modules/npcs/dialogue.md)
- 任务页读取同一份游戏状态，显示任务进度、下一步目标、待满足条件、交付对象、待领奖励合计、领赏人和柜台位置。继续游戏时恢复已保存的任务和待领记录。[任务设计](modules/quests/design.md#任务提示)
- 人物面板展示四维、相貌描述等可见信息。`game-core` 根据已保存的性别和相貌档位查出对应描述，`app` 呈现文字。幸运仅供规则结算和存档使用。[相貌](modules/character.md#相貌)
- 战斗时左侧显示双方状态，右侧显示可滚动的战斗日志，右下固定战斗操作。实际进攻命令携带本次加力投入。`game-core` 随回合返回按实际结算排序的日志段和各段对应的读数。普通回合保存后播放，需选择处置的最后一个回合先播放再等确认提交。分段出字、招名加粗、读数更新和滚动由 `app` 处理。「显示整回合」呈现当前回合的完整文字和最终读数，继续游戏使用最近一次已提交的状态。[战斗页面](modules/combat.md#战斗页面) · [特殊招式文字演出](modules/combat.md#特殊招式文字演出)
- 被放过后在探索日志中显示处置结果。死亡结果页显示对手和战败结果，提供「读取战前存档」。
- 使用原生控件呈现可操作元素和中文文本。地图用自定义 `View` 的 `onDraw()` 绘制，状态变化时请求重绘。绘制过程只读取当前状态，规则通过玩家动作推进。[Android 自定义绘制](https://developer.android.com/develop/ui/views/layout/custom-views/custom-drawing)
- 根据横屏可用窗口布局。关键按钮和文字避开刘海、系统栏与手势区，长日志在自己的区域内滚动。[Android 窗口安全区](https://developer.android.com/develop/ui/views/layout/edge-to-edge)

## 内容与本地存档

- 内容 JSON 随应用发布。地点、NPC、任务、武学和物品通过稳定 ID 关联。内容校验覆盖重复 ID、缺失引用和无效数值，随工程接入构建检查。
- 相貌配置提供四维权重、分档阈值和七档描述。内容校验确认分档阈值严格递增，每档均有男角、女角描述。[相貌](modules/character.md#相貌)
- 背包按物品 ID 保存持有量，装备位保存对物品 ID 的穿戴引用。`game-core` 计算可用数量，并在出售、交付和换装时核对占用。穿戴时检查装备门槛，出招时按当前武器检查招式条件。[ADR 0005](adr/0005-count-items-and-equipment-occupancy.md)
- 商品和换物条目关联 NPC、场景、物品、数量、价格及进度门槛。交战按场次查普通掉落表，同一 NPC 承担多个场次时各有对应引用。校验货单、各掉落组、换物条目与任务必需品的 ID 引用和数量，检查投放途径与开放条件。[物品与装备](modules/items.md)
- 一次性交换完成、隐藏秘笈领取分别与对应物品变动一起保存。采集保存可再次取得的游戏时间，参悟保存武学和已参悟记录。六派试艺保存各派线索，信物按门派 ID 记录领取进度，同步提交到确认战利品的状态更新。进入终局时检查已保存的验印结果与主线选择，终局胜利时同时保存结局和通关标记。[多区域探索与支线](modules/world.md#多区域探索与支线) · [终局挑战](modules/world.md#终局挑战)
- 玩家与各 NPC 的基础招架率由各自的角色内容配置提供。NPC 内容配置提供 1 至 100 的固定幸运。武学逐级配置威力、命中、闪避、招架、内力和暴击等适用修正。招式配置引用武学、等级和武器类型，并记录内力费用、进攻参数或防御状态效果。招式的日志内容配置提供原创描写和对应的呈现方式。[武学与战斗](modules/martial-arts.md#运用与出招) · [暴击](modules/combat.md#暴击)
- 存档按武学 ID 记录已习得等级和目标等级的练功进度，保存门派归属、拳脚和各类兵器的运用项，以及轻功、内功、招架的运用项。师门接引的物品、授艺、运用项和任务完成状态同次提交。战斗回合一起保存伤害、内力、状态剩余次数和随机进度。[武学修炼](modules/martial-arts.md#武学与修炼) · [战斗回合](modules/combat.md#战斗规则)
- NPC 的善恶值与初始好感度由内容提供，校验两个字段的整数范围。`game-core` 按稳定 ID 记录 NPC 对当前角色的好感度，游戏事件改变好感度时保存限制在范围内的结果。[战败处置](modules/combat.md#战败处置)
- 游戏使用一个自动存档槽，同一存档贯通开局到终局。存档记录结构版本、角色进度、建角时确定的性别、幸运和相貌档位，以及位置、委托与差事进度、待领奖励、铜钱、潜能、实战经验、背包、NPC 好感度、游戏时间、饥饿度、口渴度和继续当前战斗或回到对应结果页所需的状态。同时至多保留一场待处理的战斗结果。
- 开战时在同一槽内保存触发战斗前的完整探索快照与当前战斗。每回合提交时保留该战前快照。死亡结果已保存后重启，选择继续游戏时返回同一死亡结果页。角色存活结束战斗或完成死亡读档时，随对应状态提交清除战前快照。[ADR 0004](adr/0004-keep-pre-battle-save.md)
- 建角和游戏动作在规则规定的结算时点保存。`game-core` 在确认建角时生成幸运并用建角四维计算相貌档位，由 `app` 随初始角色状态一次提交。文件位于 `filesDir`，由 `app` 在后台串行读写，通过 `AtomicFile` 提交完整快照。重启以最近成功提交的状态作为继续入口。[Android 私有存储](https://developer.android.com/training/data-storage/app-specific) · [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile)
- 写入失败时提示并允许重试提交同一份待保存快照。读档失败时保留文件并提示原因，玩家明确确认新游戏后才替换已有档。兼容的旧档通过版本迁移恢复，迁移前后以存档样例验证角色进度和内容引用。
- 首胜指定挑战时，将经验增量与首胜标记一起保存。高阶请教读取开局以来的累计实战经验。存档保留当前气血、有效气血上限和内力，分别保存声望与通缉。相关玩法按同一份存档中的成长和剧情条件开放。[玩法模块索引](gameplay-rules.md)

### 随包样例与校验

`app` 从 assets 读取 UTF-8 的 [content/sample.json](../app/src/main/assets/content/sample.json)，交由 `game-core` 的 `ContentLoader` 解码和校验。Android 构建在 `preBuild` 前运行 JVM 任务 `:game-core:validateContent`，读取同一份源文件并显示校验失败的 JSON 路径。

- `contentVersion` 为正整数，随样例状态传给存档入口。地点、NPC、任务、武学和物品各表的 ID 以小写字母开头，由小写字母、数字和单个下划线组成，同表唯一。样例使用 `sample_` 前缀。
- 起点和 NPC 的地点引用地点表。任务发布人与交付对象引用 NPC 表，奖励中的物品与授艺分别引用物品和武学表。奖励铜钱、潜能和经验为非负整数。物品数量和授艺等级为正整数，授艺等级以对应武学的最高等级为上限。
- `appearance.weights` 的四项对应膂力、敏捷、悟性和根骨。六个 `thresholds` 是第 2 至 7 档的最低分，严格递增。七条 `descriptions` 按第 1 至 7 档排列，每档提供男女描述。[相貌规则](modules/character.md#相貌)

验收方法见 [验收规则](acceptance.md)，玩法和版本范围见 [玩法范围](gameplay.md)。
