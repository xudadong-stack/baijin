# 测试驱动开发

从 [玩法范围](../../../docs/gameplay.md) 和 [验收规则](../../../docs/acceptance.md) 选定一个可观察行为。角色、潜能、武学与战斗优先走 `game-core` 的 JVM 入口。涉及触控、存档文件或生命周期的行为走 `app` 的 Android 入口。

## 红

写一个聚焦的行为测试，从已确认规则推导期望值。运行并核对失败原因确实是待实现或修复的行为。若首次通过，查明行为是否已经存在，或测试输入是否触及了目标分支。

## 绿

实现使测试通过的最小生产改动。保留现有调用入口和模块依赖方向，重跑测试并核对退出状态。

## 重构

有助于理解时再整理命名、重复和结构。每次有效整理后重跑行为测试，并按 [完成前验证](../verification-before-completion/SKILL.md) 选择受影响的检查。

优先断言玩家能观察到的状态和结果。例如同一条一次性委托重复提交时，核对潜能变化和完成标记。战斗测试使用固定初始状态与随机种子。测试替身集中在随机源和设备 I/O 等边界。

运行以 [README.md](../../../README.md) 已登记的工程入口为准。测试入口尚未建立时，先核对本次范围中是否包含建立测试环境，并记录当前可验证的部分。
